# Revenue Flywheel Verification Roles

The implementation is reviewed from four independent perspectives:

1. **Requirements Coverage Auditor** — checks every Issue #58 source requirement against schema/runtime/test evidence.
2. **Execution Compliance Auditor** — checks each implementation/release phase against the approved operating plan.
3. **QA/Governance** — runs normal, edge, adversarial and regression cases, with special emphasis on fabricated claims, suppression and approval boundaries.
4. **Revenue Operations & Cohesion** — checks stage handoffs, follow-up availability, queue aging and dead-end states.

A green repository test is necessary but not sufficient. Production requirement status is updated to `verified` only after applicable schema, runtime and synthetic/live checks are confirmed.
